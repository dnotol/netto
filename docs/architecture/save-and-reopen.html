How a plan is saved and opened again

Saved plans live in the browser, in one versioned document of Netto's own, never the inputs serialised as they are in memory. A plan is read back exactly as it was saved or not at all; an older document is brought forward one version at a time. This page follows a save, the read at start-up, opening a plan, and the export to a file.

As of main 29cbc9529 October 2026

Save, start-up, open

SavedPlans holds the book of plans for the tab and is the only writer of netto.plans. PlanStorage maps RiverInputs to its stored records (StoredBook, StoredInputs) and back, and holds the version and the patches. The plan page only ever receives a readable RiverInputs.

The stored document

{"version":9,"today":id,"opened":id,"plans":[{"id","name","inputs":{…}}]}, written by a source-generated serializer (camelCase, string enums, unmapped members refused). Each leaf of inputs is {"value":…,"origin":"Example|Default|Yours"}; the municipality is stored by its INS code and rate. Plans store no region: every plan is read as Walloon.

Versions and their patches

A new input is a new field, a new PlanStorage.Version and one patch adding it as frozen literal JSON, never read from RiverInputs.Example. Each patch adds members with Add, which refuses one already present.

PatchAdds
1 → 2The company car, out of the plan
2 → 3The copyright royalty, out of the plan
3 → 4What the fund bills, none given
4 → 5Whether the royalty follows the pay: fixed when the user had typed it
5 → 6The car's private cost, none given
6 → 7The company contribution's band (lower, default) and the fund's fee rate, none given
7 → 8The household, out of the plan
8 → 9The household's status and its dependants

Guarded by RiverInputsShapeTests (the shape of RiverInputs), StoredPlanDocuments (a captured document of each version 1 to 9), PlanStorageTests and SavedPlansTests. Decisions: a strict versioned format, migrated a version at a time, plans stay in the browser.

Export and import

  • Export writes SavedPlans.Export(), the same document as netto.plans, to netto-plans-<date>.json through plan-file.js (a Blob and a temporary download link).
  • Import reads a file of up to 1 MB through Blazor's InputFile and the same PlanStorage.Read, so a file of any version is patched. Readable plans are added with new ids; the file's Today is starred only if none is; unreadable plans are skipped and counted.

Known gaps, read from the code: the unreadable copy happens at each start-up into one slot, and nothing reads it back; an unreadable older plan is written back inside a version 9 document, so a later build could not patch it.
