Netto · architecture page

What runs, and where the figures stay

Netto is one Blazor WebAssembly app. The server only hands the browser its files; the tax engine runs in the browser tab, and the plans a user saves stay in that browser or in a file they export. This page shows those parts, what each holds, and the settings that shape them.

As of feature/calendar-in-optimiser-sankey-toggle a35b94411 November 2026

The parts

Locally, Rider or dotnet run starts Netto.AppHost, an Aspire AppHost whose only resource is the web host. Netto.Web serves the WebAssembly bundle and static files and nothing else: no API, no endpoint that receives a user's figures. In the browser, Netto.Web.Client draws every page and calls Netto.Core, the tax engine, in-process. What the user keeps (their saved plans and a few preferences) goes to the browser's localStorage, or to a JSON file they export and import again.
